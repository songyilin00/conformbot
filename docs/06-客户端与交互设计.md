# 客户端与交互设计

> 本文档定义「仪表盘（审计控制台）」的页面与交互。标注 【源自项目文档】 源自早期规划文档（已并入本套文档；§ 指其原章节号，如 §6.1 / §7.4 / §9.1）；标注 【建议/待确认】 为推演。
>
> ⚠️ 记住身份铁律：**界面是它的「审计控制台」，不是它的主入口**（`01` §二）。

## 一、设计取向【源自项目文档】

- **日常静默的仪表盘**：用户不需要每天打开，后台持续监控，仅在信号达到「整改级」时主动推送。参考 QIMA Cyberexpert 的「准备层」定位——**不是实时告警轰炸**。
- **信号分级严格**：日常输出形如「本周新增 2 个监控项，0 个需立即处理」，而非「⚠️ 新漏洞！」。
- 原型已产出（第 109 / 123 轮）：亮色 SaaS 后台风格，含侧边栏导航 + 仪表盘 + 各模块卡片/表格；第 123 轮版本带交互逻辑（变更评估弹窗分步动画、漏洞工单 SLA 进度条、审计日志哈希链）。

## 二、页面与路由结构【建议/待确认】

```text
/
├── /dashboard          # 合规状态总览（默认首页）
├── /board              # 合规看板（按产品/固件）
├── /changes            # 变更评估
├── /tickets            # 漏洞工单
├── /audit              # 审计与证据
└── /settings           # 设置（产品、集成、推送）
```

## 四、变更评估流程【源自项目文档】

提交一次变更 → 分步动画 → 结构化结论弹窗 → NB 证书提示。

```text
┌─────────────────────────────────────────────┐
│ 变更评估 (2/3)                               │
├─────────────────────────────────────────────┤
│ 变更：mbedtls 2.28.1 → 2.28.4                │
│ ✓ 变更性质识别                               │
│ ✓ 触及面判定：加密库 / 认证协议              │
│ ⟳ 结论生成…                                  │
├─────────────────────────────────────────────┤
│ 结论：需重新评估（reassess）                 │
│ 依据：触及 SCM-1 通信加密要求                │
│ 提示：需向公告机构备案 / 可能需差异测试      │
└─────────────────────────────────────────────┘
```

> 未触及时：标记「内部评估完成，证据假设未变」，记录归档（`04` §七）。

## 五、漏洞工单【源自项目文档】

- 提供公开漏洞报告入口（研究员通过入口提交，而非在 Twitter 曝光）。
- 流程：自动去重 → 初步分类 → 通知厂商 → 给修复建议 → 跟踪到关闭。
- 厂商无需自建 PSIRT，却能对外宣称「有正规漏洞响应渠道」。
- UI：**SLA 进度条**（第 123 轮原型）。

```text
┌─────────────────────────────────────────────┐
│ 漏洞工单 #T-0212        严重级：高   状态：修复中│
├─────────────────────────────────────────────┤
│ SLA: ████████░░  已用 36h / 72h              │
│ 来源：公开报告入口    已去重：是             │
│ 时间线：提交 → 分类 → 已通知厂商 → 修复中    │
└─────────────────────────────────────────────┘
```

## 六、多框架告警视图【源自项目文档】

- 支持**按框架筛选、按严重级排序**；
- 但「同时触发」这个事实必须**原样呈现**（不合并）。

```text
筛选：[框架 ▼ EN 18031]  排序：[严重级 ▼]
CVE-2026-xxxx  框架=EN 18031  依据=GEC-1      严重级=高
CVE-2026-xxxx  框架=CRA       依据=§14 报告义务 严重级=高
```

## 八、通知与信号分级【源自项目文档】

| 事件 | 呈现 |
| :--- | :--- |
| 无整改级信号 | **静默**（周报摘要） |
| 达到整改级 | 主动推送（按 BOM/框架过滤） |
| 必须修复 / 需重新评估 | 高优先级通知 + 看板红色提示 |
| 门禁拦截（OTA 发布前） | 通知 + 依据链接 |
| 审计链校验失败 | 高优先级通知 + 建议导出留证 |

## 九、可访问性与一致性【建议/待确认】

- 颜色语义与安全语义一致：绿=正常、黄=警告、红=拒绝/需处理（注：与股票涨跌红绿约定无关，此处遵循通用安全语义）。
- 所有「危险动作」（导出审计、门禁放行）需二次确认并写入审计。
- 文案避免夸大承诺，遵循项目「不承诺赔付 / 不承诺包过」的表述原则。
