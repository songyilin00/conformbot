# 验收清单

> 本文档定义各 Phase 验收标准、判断准确性基准、法规时间表校验。对照 `03-分阶段任务清单.md` 使用。
> 【建议/待确认】为推演；法规节点【源自项目文档】（早期规划文档，已并入本套文档）。

## 一、各 Phase 验收标准

### Phase 0（地基）
- [ ] 十类 ER 实体表可创建，字段/索引符合 `04` §一
- [ ] 可插入审计记录并校验哈希链（`04` §九）
- [ ] CSV/Excel 样例 SBOM 可导入，组件数与版本规范化正确
- [ ] CycloneDX 与 SPDX 样例文件均可解析

### Phase 1（判断引擎）
- [ ] 多层过滤四态标签输出正确（含「不适用」排除）
- [ ] CVSS/EPSS 仅作排序、非唯一依据（用例验证）
- [ ] 变更评估能识别触及面，输出 reassess / recertify 与 NB 提示
- [ ] 「未触及」变更标记为「内部评估完成，证据假设未变」并归档

### Phase 2（主动推送与看板）
- [ ] 同一 CVE 触碰 EN 18031 与 CRA 时产生**两条独立告警**（不合并）
- [ ] 信号分级：无整改级时静默；有则主动推送且带依据
- [ ] 健康度色标（绿/黄/红）准确反映合规状态

### Phase 3（静默修复 + 语义级分析）
- [ ] 含未披露修复的组件更新能被标记为「静默安全修复」
- [ ] 本地 LLM 输出带依据的语义级初判，且不越位终裁

### Phase 4（对接与门禁）
- [ ] 能从 PLM（MCP）拉取成分基线
- [ ] OTA 发布前可按结论放行/拦截，结论与依据写入审计
- [ ] 判断结果可回写 ECN / OTA

## 二、判断准确性基准【建议/待确认】

| 基准项 | 期望 |
| :--- | :--- |
| 组件版本匹配 | 精确到补丁级（如 `5.15.104`），不漏不误 |
| 可利用性证据 | 正确识别 PoC / CISA KEV / 在野证据 |
| 保护范围判定 | 正确区分安全资产 vs 非核心资产 |
| 状态标签一致性 | 同输入必得同标签（可复现） |
| 多框架告警 | 每个被触碰框架各一条，不合并 |

> 建议维护一个**样例 CVE 集 + 期望标签**作为回归基准（`07` §三）。

## 三、法规时间表校验【源自项目文档】

| 法规 | 节点 | 校验点 |
| :--- | :--- | :--- |
| EN 18031 系列 | 2025-08-01 强制 | 条款库含该版本；准入判断生效 |
| CRA §14 | 2026-09-11 生效 | 报告义务（24h/72h）纳入判断 |
| CRA 全面适用 | 2027-12-11 | 全生命周期管理要求生效 |

- [ ] 条款库版本与上述时间表一致
- [ ] 报告义务（24h 预警 / 72h 详报 ENISA+CSIRT）作为独立合规事实呈现

## 四、安全/合规专项验收

- [ ] 审计记录只追加、哈希链可校验（`04` §九）
- [ ] 无「保证过认证 / 赔付」类表述（`07` §七）
- [ ] GEC-1 终裁不由系统自动给出（`04` §五）
- [ ] 告警不跨框架合并（`04` §八）
- [ ] 文档/对话数据不外传（LLM 本地化）

## 五、验收流程

每个 Task 完成后：
1. 代码审查：对照 `07-通用开发规范.md`
2. 功能测试：按 `05-接口与协议规范.md` 验证接口
3. 判断专项：对照本文件「判断准确性基准」
4. 在本文件勾选对应项
5. 更新 `CONTEXT.md` 与 `docs/handoff/phase-N-complete.md`
6. 回复「Task X.X 验收通过，继续下一个任务」
