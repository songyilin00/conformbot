# 通用开发规范

> 【建议/待确认】本文档定义 ConformBot 的代码规范、判断可复现性、测试、日志、配置与发布规范。结构参照 `barkguard/docs/07-通用开发规范.md`。

## 一、代码规范

| 项 | 约定 |
| :--- | :--- |
| 命名 | 变量/函数 snake_case（Python）/ camelCase（前端）；类型 PascalCase |
| 目录 | 按分层组织：`ingest/`（接入）`engine/`（判断）`store/`（模型）`push/`（推送）`web/`（前端） |
| 品牌与代码 | 技术代号与品牌同名（`ConformBot`）；仓库/模块命名统一采用此名 |
| 注释 | 公开函数必须有文档注释；判断逻辑须注明所依据的条款 |
| 依赖 | 锁定版本；外部数据源客户端须可 mock |

## 二、判断可复现性规范（本项目特有，最高优先）

1. **同输入必得同结论**：给定相同的 SBOM + CVE 数据 + 条款版本，判断结果必须完全一致。
2. **判据可版本化**：条款库、阈值、规则集均带版本号；结论记录其判据版本。
3. **规则与数据分离**：规则不硬编码进代码逻辑，走配置/数据表。
4. **结论必有依据**：任何输出（状态标签 / reassess / recertify）都必须携带 `basis`（条款版本 + 数据点 + 命中规则）。
5. **判据缺失不判「合规」**：判据不可用时返回「待定」并提示补全（延续「失败方向安全」思路）。

## 三、测试规范

| 类型 | 要求 |
| :--- | :--- |
| 单元测试 | 多层过滤（`04` §四）正/反用例；版本匹配（补丁级）边界 |
| 边界测试 | 静默修复（无 CVE 但有修复）、版本不匹配排除 |
| 一致性测试 | 同输入重复运行结论一致（可复现性） |
| 集成测试 | SBOM 导入 → 判断 → 告警 → 审计 全链路 |
| 回归集 | 维护样例 CVE 集 + 期望状态标签，作为回归基准 |

## 四、日志与审计规范

1. 结构化日志（JSON），含时间、模块、实体 ID。
2. **判断日志与审计记录分离**：审计记录为「证据」，只追加、哈希链相连（`04` §九）。
3. 禁止在日志中输出凭据、密钥、完整对话内容。
4. 错误必须可观测：外部数据源失败、判据缺失须显式记录并告警。

## 五、配置管理

| 配置 | 说明 |
| :--- | :--- |
| 数据源凭据 | NVD/EUVD 等 API Key，走环境变量/密钥管理 |
| 条款库版本 | 显式声明当前使用的 EN 18031 / CRA 版本 |
| 推送策略 | 信号分级阈值、按 BOM/框架过滤规则 |
| LLM 配置 | 本地模型地址、超时、文档不外传开关 |

## 六、版本与发布规范

1. 语义化版本；判断逻辑变更须在变更日志中标注影响面。
2. **法规条款绑定**：EN 18031 / CRA 条款更新时，条款库版本递增，并标注对既有结论的影响。
3. 发布前对照 `08-验收清单.md`；生产路径禁止未处理异常。
4. 发布记录同步到 `CONTEXT.md` 与 `handoff/`。

## 七、合规与安全红线（不可违反）

1. 不得给出「保证通过认证」类表述与接口。
2. GEC-1 最终「可利用性」不得由系统自动终裁（`04` §五）。
3. 不跨框架自动合并/抑制告警（`04` §八）。
4. 文档/对话数据不外传（LLM 本地化）。
